> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold the Next.js 15 app, define domain types and pricing, build the PostGIS schema with corrected RLS, and run the stack locally in Docker Compose.

**Architecture:** One Next.js 15 App Router repo. Pure logic (`types/`, `lib/pricing.ts`) has no I/O. Database access goes through `lib/db/`. Migrations are plain SQL files run by a small runner.

**Tech Stack:** Next.js 15, React 19, TypeScript strict, Tailwind CSS v4, Zod, `pg`, Vitest, PostgreSQL 16 + PostGIS 3.4, Docker Compose.

**Spec:** `/home/ubuntu/original/food_prompt.md` §1–3, §6; PDF in `/home/ubuntu/original/`. Decisions in `2026-11-03-00-roadmap.md` apply here.

## Scope

In: scaffold, domain types, pricing, schema and RLS, migration runner, local Docker stack.
Out: any route UI, auction logic, voice, integrations, EC2 (see roadmap).

**Build deviations (recorded):**
- Node runs only in containers; the host has no Node (owner decision; replaces the earlier install to `/home/ubuntu/.local/node`).
- Commits use an identity from the environment.
- The runner bootstraps roles and extensions as the instance superuser once, before `SET ROLE food_admin` (one-time bootstrap, allowed by tech decisions).
- TypeScript pinned to `^5.9.3`.
- The in-container verify check (`scripts/verify-stack.sh`) replaces the host-port check.

## Global Constraints

- Next.js 15 App Router; Tailwind CSS v4; TypeScript `strict: true`.
- PostgreSQL 16 `postgis/postgis:16-3.4`; extensions `postgis`, `uuid-ossp`, `pgcrypto`; Redis Alpine.
- `GEOGRAPHY(Point, 4326)`; SQL points `ST_MakePoint(lng, lat)`.
- Money `NUMERIC(10, 2)`; `round2` half-up.
- Mesh fee `0.035`; GST `0.05`; floor margin `0.05`.
- Port `3000`.
- The host runs Docker only. No Node, npm, or npx on the host: every Node command runs in a container (`node:22-alpine`, run as UID 1000, `--network host` to reach the local `localhost:5432` and `6379` ports), as shown in the Run lines.

## Review Focus

1. Out-of-range coordinates (`lat: 250`) are rejected by the schema before any query. Owned by Task 2.
2. A new kitchen shows no fake rating: `rating_aggregate` defaults to `0.00`. Owned by Task 4.
3. A rating row cannot exist without a completed order, even if the service is misused. Owned by Task 4.
4. A restaurant's staff cannot read another restaurant's KDS tickets. Owned by Task 4.
5. A bundle quote with a zero or negative price is rejected rather than producing a negative fee. Owned by Task 3.

### Task 3: Pricing Helpers

**Files:**
- Create: `lib/pricing.ts`
- Test: `tests/pricing.test.ts`

**Interfaces:**
- Consumes: none
- Produces:
  - `MESH_PROTOCOL_FEE_RATE = 0.035`, `STATUTORY_GST_RATE = 0.05`, `DEFAULT_FLOOR_MARGIN = 0.05`
  - `round2(n: number): number` (half-up; `round2(2.345) === 2.35`)
  - `interface PriceLine { basePrice: number; quantity: number }`
  - `interface BundleQuote { baseSubtotal: number; meshFee: number; kitchenNet: number; passesFloor: boolean }`
  - `quoteBundle(lines: PriceLine[], offeredPriceInr: number, floorMargin?: number): BundleQuote`
  - `gstOn(subtotal: number, rate?: number): number`; `splitGst(gst: number): { cgst: number; sgst: number }` (2.5% each of subtotal, so each half of the 5% total)

Rule (decision 2): `meshFee = round2(offered × 0.035)`; `kitchenNet = round2(offered − meshFee)`; `passesFloor = kitchenNet ≥ round2(baseSubtotal × (1 − floorMargin))`.

### Task 4: PostGIS Schema, Migrations, and RLS

**Files:**
- Create: `db/migrations/001_init.sql`, `lib/db/client.ts`, `lib/db/migrate.ts`, `scripts/migrate-cli.ts`, `tsconfig.scripts.json`
- Test: `tests/db/rls.test.ts`

Tests need `DATABASE_URL` pointing at a PostGIS 16 instance (Task 5 provides one).

**Interfaces:**
- Consumes: none
- Produces:
  - `getPool(): pg.Pool`: reads `DATABASE_URL`, throws `Error('DATABASE_URL is not set')` if missing.
  - `runMigrations(pool: pg.Pool, dir?: string): Promise<string[]>`: applies `*.sql` in lexical order, each in a transaction, under `pg_advisory_xact_lock`; records in `schema_migrations(name text primary key, applied_at timestamptz default now())`; returns names applied this run.
  - `asRole<T>(pool, userId: string | null, fn: (c: pg.PoolClient) => Promise<T>): Promise<T>`: transaction that runs `SET LOCAL ROLE food_app` and `set_config('app.user_id', $1, true)`, then commits. When `userId` is `null`, pass `''` to `set_config`, never SQL `NULL`; `app_current_user_id()` maps `''` to `NULL`, so the query sees no rows.

**Fixes to md §2 DDL, all applied in `001_init.sql` with a header comment:**
1. `dining_tables.restaurant_id` has no type → `UUID`.
2. `auth.uid()` is Supabase-only → `app_current_user_id()` returns `NULLIF(current_setting('app.user_id', true), '')::uuid`. Replace every use.
3. `current_setting('request.headers', true)::json->>'x-session-token'` is Supabase-only → `current_setting('app.session_token', true)`.
4. Multi-tenant gap: `kds_tickets_staff_isolation` lets any staff read any restaurant → add nullable `users.restaurant_id UUID REFERENCES restaurant_nodes(id)`; scope the policy to `kds_tickets.restaurant_id = (SELECT restaurant_id FROM users WHERE id = app_current_user_id())` for roles `restaurant_staff`, `kitchen_lead`, `platform_admin`.
5. Ratings not gated on an order → add `order_refs(id UUID PK DEFAULT gen_random_uuid(), restaurant_id UUID NOT NULL REFERENCES restaurant_nodes(id), diner_user_id UUID NOT NULL REFERENCES users(id), session_id UUID NULL, status TEXT NOT NULL CHECK (status IN ('open','completed')), created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL)`. Add FK `verified_customer_ratings.order_ref_id → order_refs(id)`. Insert policy: `WITH CHECK (diner_user_id = app_current_user_id() AND EXISTS (SELECT 1 FROM order_refs o WHERE o.id = order_ref_id AND o.status = 'completed' AND o.diner_user_id = app_current_user_id() AND o.restaurant_id = verified_customer_ratings.restaurant_id))`.
6. `restaurant_nodes.rating_aggregate` default `0.00` (was `5.00`), decision 1. Add `total_verified_reviews` unchanged at 0.
7. `mesh_food_auctions.expires_at` stays `NOW() + INTERVAL '90 seconds'` (decision 4).
8. Roles, both created in `001_init.sql` guarded by `IF NOT EXISTS`: `food_app` (`NOLOGIN`, RLS enforced; used by all request traffic) and `food_sync` (`NOLOGIN`, `BYPASSRLS`; used only by the nightly menu sync job and maintenance). Also `food_admin` (`NOLOGIN`, `BYPASSRLS`, not superuser; used only by the migration runner, seed scripts, and test fixtures; owns the tables it creates; the migration connection runs `SET LOCAL ROLE food_admin` before any DDL). No code path runs as a superuser or the table owner at runtime. `GRANT USAGE ON SCHEMA public` to `food_app`, `food_sync`, and `food_admin`; `GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES` to both; `ALTER TABLE … FORCE ROW LEVEL SECURITY` on each RLS table.

- [ ] **Step 2: Write `docker-compose.yml`**

- Every service sets `restart: unless-stopped`, hard `cpus`, `mem_limit`, `mem_reservation`, `pids_limit`, and a json-file log cap (`max-size: "10m"`, `max-file: "3"`). Limits are ceilings, not reservations; caps total 4.0 CPUs on the 4-vCPU host (tech decisions, "Container resource limits").

- `redis`: `redis:7-alpine`; `container_name: food-os-redis`; command `redis-server --appendonly yes --maxmemory 256mb --maxmemory-policy allkeys-lru`; volume `redisdata:/data`; healthcheck `redis-cli ping`; networks `backend` only, no ports. - `app`: `build: .`; `container_name: food-os-app`; `expose: ["3000"]` only, no `ports`; networks `shared` (`external: true`, created by `proxy_server/create-shared-network.sh`) and `backend`; limits `cpus: 1.5`, `mem_limit: 1g`, `mem_reservation: 512m`, `pids_limit: 512`; env `DATABASE_URL=postgres://food:${POSTGRES_PASSWORD}@db:5432/food_os`, `REDIS_URL=redis://redis:6379`; `depends_on` both with `condition: service_healthy`; healthcheck `wget -qO- http://localhost:3000/api/health`.
- Top-level `networks: { backend: { driver: bridge }, shared: { external: true } }`.
- Top-level named volumes with fixed names and labels: `pgdata` (`name: food-os-pgdata`, labels `app: food-os`, `purpose: postgres-data`) and `redisdata` (`name: food-os-redisdata`, labels `app: food-os`, `purpose: redis-aof`). `docker compose down` never removes them; removal needs `-v` and an explicit operator step.
