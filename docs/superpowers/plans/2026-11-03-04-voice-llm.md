# Plan 04: Voice and LLM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the voice pipeline and LLM orchestration behind `POST /api/voice/turn`: provider interfaces with real adapters and fakes, Hinglish handling, a Zod-validated tool-calling orchestrator, per-turn latency budgets, a LiveKit session wrapper, and the audio-reactive orb.

**Architecture:** Every external service sits behind an interface in `lib/voice/types.ts` and `lib/webrtc/transport.ts`. Real adapters live in `lib/voice/providers/` and `lib/voice/llm/`, are marked `server-only`, and are only constructed when their key is present. Tests use the fakes in `lib/voice/fakes.ts` and a `ManualClock`, so no test calls a paid API and latency assertions are deterministic. The orchestrator in `lib/voice/orchestrator.ts` is the only code that turns model output into an action, and it validates every output with Zod before returning it.

**Tech Stack:** Next.js 15 App Router route handlers, React 19, TypeScript strict, Zod v4 (`z.toJSONSchema`), Vitest, `@anthropic-ai/sdk`, `@google/genai`, `livekit-client`, `@ricky0123/vad-web` (Silero VAD, ONNX/WASM), `server-only`.

**Spec:** `/home/ubuntu/original/food_prompt.md` §1 (voice pipeline and LLM orchestrator), §3 (`CartUpdateSchema`, `DeliveryIntentSchema`), §4 (Route 1 Hinglish transcript); PDF in `/home/ubuntu/original/` (latency: audio ingress under 200 ms, NLU under 800 ms, TTS first audio under 150 ms, glass-to-glass under 120 ms; Hindi and Hinglish route through Sarvam). Decisions in `2026-11-03-00-roadmap.md` and `2026-11-03-tech-decisions.md` apply here; the LLM section of the tech decisions is binding.

**Depends on:** Plan 01 (`types/food-os.ts` exports `CartUpdateSchema`, `CartUpdate`, `DeliveryIntentSchema`, `DeliveryIntent`). Plans 02 and 03 are not imported by code in this plan; see the Open Items section for how the action plan is handed to them.

## Scope

In:
- (a) Provider interfaces and adapters: `SttProvider` (Deepgram Nova-3, plus fake), `TtsProvider` (Cartesia Sonic, plus fake), `TranslationProvider` (Sarvam, plus fake), `VadProvider` (Silero WASM wrapper, plus an energy-based fallback used in tests).
- (b) LiveKit client session wrapper with a fake transport.
- (c) `LlmProvider` with a Claude adapter (`claude-haiku-5-5`), a Gemini adapter (`gemini-2.5-flash`), and a fake, selected by the rules in the tech decisions.
- (d) Tool-calling orchestrator: `cart_update` uses `CartUpdateSchema`, `delivery_intent` uses `DeliveryIntentSchema`, a `respond` tool carries the reply. Every model output is validated; an invalid output is retried once, then the turn returns a safe "I did not catch that" reply with no action.
- (e) Hinglish handling: language detection, translation to English for the LLM, reply in the user's language.
- (f) Latency instrumentation for the PDF budgets, recorded per turn; a test fails when a fake pipeline exceeds its budget.
- (g) Canvas audio-reactive orb driven by a `level` value.
- (h) `POST /api/voice/turn`: takes a transcript, returns a validated action plus reply text and timing.

Out:
- Writing cart rows or delivery auctions (Plans 03 and 02). This plan returns a validated action; it does not persist it.
- LiveKit token minting (server-side, needs `LIVEKIT_API_KEY` and `LIVEKIT_API_SECRET`); see Open Items.
- Rate limiting and WAF (Plan 07).
- Glass-to-glass measurement on a device (120 ms budget); see Open Items.
- Pure-Hindi (Devanagari) replies, and Tamil, Telugu, Kannada, Marathi (roadmap: later).

## Global Constraints

- Node.js 22 LTS; TypeScript `strict: true`; Next.js 15 App Router; React 19; Zod v4.
- Tests never call a paid API. Every adapter takes an injected `fetch` or SDK client; tests inject mocks. Tests set their own env and never read `.env*`.
- Provider selection (binding, from tech decisions):
  - `LLM_PROVIDER=claude|gemini` overrides everything. An unknown value throws. An override whose key is missing throws.
  - Unset: Claude when `ANTHROPIC_API_KEY` is present; else Gemini when `GEMINI_API_KEY` is present; else the fake, with one `warn` log line.
  - Speech and translation adapters are real only when their key is present: `DEEPGRAM_API_KEY`, `CARTESIA_API_KEY`, `SARVAM_API_KEY`. Otherwise the matching fake is used.
- Both LLM adapters run with `temperature: 0.1`. Every tool call is validated with Zod before any state change.
- Keys live only in `.env` and `.env.local` (git-ignored). Keys are never logged, never returned in responses, and never sent to the browser. Every adapter module starts with `import 'server-only';`, except `lib/webrtc/*` and `components/voice/*`, which run in the browser and hold no keys.
- Latency budgets (PDF): audio ingress under 200 ms, NLU under 800 ms, TTS first audio under 150 ms. "Under" means a value of exactly the limit is a violation.
- The transcript is not logged (it may contain personal data). Logs carry timings, outcome, and provider names only.
- App listens on port `3000`.
- Languages: English and Hinglish (romanized Hindi mixed with English). Reply language is `en` or `hi-en`.

### Task 2: Fake Providers and Manual Clock

**Files:**
- Create: `lib/voice/fakes.ts`
- Test: `tests/voice/fakes.test.ts`

Fakes take an optional `ManualClock` and a `delayMs`. When called, a fake calls `clock.advance(delayMs)` before returning, so latency tests run without real time. `FakeLlm` throws on an empty queue, so an unexpected extra LLM call fails the test instead of passing silently.

**Interfaces:**
- Consumes: `lib/voice/types.ts` (Task 1).
- Produces:
  - `class ManualClock implements Clock { now(): number; advance(ms: number): void }` (starts at 0)
  - `class FakeStt implements SttProvider { constructor(opts: { text: string; language?: LangCode; clock?: ManualClock; delayMs?: number }) }`, name `'fake'`
  - `class FakeTts implements TtsProvider { constructor(opts: { clock?: ManualClock; firstChunkDelayMs?: number; chunks?: number }) }`, name `'fake'`; yields `chunks` (default 2) small `Uint8Array`s
  - `class FakeTranslation implements TranslationProvider { constructor(opts: { table?: Record<string, string>; clock?: ManualClock; delayMs?: number }) }`, name `'fake'`; returns `table[text]` or the input unchanged; records `calls: Array<{ text: string; from: LangCode; to: LangCode }>`
  - `class FakeVad implements VadProvider { constructor(script: VadFrameResult[]) }`, name `'fake'`; returns scripted results in order, then `{ speech: false, level: 0 }`
  - `class FakeLlm implements LlmProvider { constructor(outputs: Array<LlmOutput | Error>, opts?: { clock?: ManualClock; delayMs?: number }); readonly requests: LlmRequest[] }`, name `'fake'`, model `'fake'`; throws `Error('FakeLlm: no scripted output left')` when the queue is empty; throws any queued `Error`

### Task 3: Latency Instrumentation and Budget Check

**Files:**
- Create: `lib/voice/latency.ts`
- Test: `tests/voice/latency.test.ts`

Budgets are the PDF values. A stage is a violation when its measured time is greater than or equal to its limit ("under 200 ms"). The pipeline test composes fakes from Task 2 into a turn of ingress, NLU, and TTS stages. It asserts no violations for the fake config and asserts that a slowed stage is reported, so the guard is proven to fire.

**Interfaces:**
- Consumes: `Clock`, `ManualClock`, `FakeStt`, `FakeTts`, `FakeLlm` (Tasks 1 and 2).
- Produces:
  - `const BUDGETS_MS = { audio_ingress: 200, nlu: 800, tts_first_audio: 150 } as const`
  - `type Stage = keyof typeof BUDGETS_MS`
  - `type TurnTiming = { [S in Stage as `${S}_ms`]?: number }` (keys `audio_ingress_ms`, `nlu_ms`, `tts_first_audio_ms`)
  - `class TurnTimer { constructor(clock: Clock); measure<T>(stage: Stage, fn: () => Promise<T>): Promise<T>; record(stage: Stage, ms: number): void; snapshot(): TurnTiming }`. `measure` records elapsed clock time in a `finally`, so failed stages are still timed.
  - `checkBudgets(t: TurnTiming): Array<{ stage: Stage; limitMs: number; actualMs: number }>`. Reports stages where the recorded value is `>= limit`. Missing stages are skipped.

```ts
import { ManualClock, FakeStt, FakeTts, FakeLlm } from '@/lib/voice/fakes';

  expect(BUDGETS_MS).toEqual({ audio_ingress: 200, nlu: 800, tts_first_audio: 150 });

test('measure records elapsed fake-clock time, including on throw', async () => {
  const clock = new ManualClock();
  const timer = new TurnTimer(clock);
  await timer.measure('nlu', async () => clock.advance(300));
  await expect(timer.measure('nlu', async () => { clock.advance(10); throw new Error('x'); })).rejects.toThrow('x');
  expect(timer.snapshot().nlu_ms).toBe(10);

  expect(checkBudgets({ audio_ingress_ms: 199, nlu_ms: 800, tts_first_audio_ms: 149 }))
```

### Task 4: Deepgram, Cartesia, and Sarvam Adapters with Key Gating

**Files:**
- Create: `lib/voice/providers/deepgram.ts`, `lib/voice/providers/cartesia.ts`, `lib/voice/providers/sarvam.ts`, `lib/voice/providers/select.ts`

Each adapter takes `{ apiKey: string; fetchImpl?: typeof fetch }` and defaults `fetchImpl` to global `fetch`. Tests always inject `fetchImpl`. Endpoint paths follow the provider docs as known at planning time (see Open Items: verify each path against the live docs before the first real call).

Endpoints used:
- Deepgram: `POST https://api.deepgram.com/v1/listen?model=nova-3&language=multi&smart_format=true`, header `Authorization: Token <key>`, body = raw PCM16 16 kHz mono, `Content-Type: audio/l16;rate=16000;channels=1`. Response: `results.channels[0].alternatives[0].transcript`, `confidence`.
- Cartesia: `POST https://api.cartesia.ai/tts/bytes` (streamed in later work), headers `X-API-Key`, `Cartesia-Version`; body JSON `{ model_id: 'sonic-2', transcript, voice, output_format }`. The adapter yields the response body as chunks.
- Sarvam: `POST https://api.sarvam.ai/translate`, header `api-subscription-key`; body JSON `{ input, source_language_code, target_language_code, model: 'mayura:v1' }`; response `translated_text`.

Language mapping: `hi` and `hi-en` map to `source_language_code` `hi-IN`. Use `en-IN` for English targets. Confirm the Sarvam language codes at implementation time.

**Interfaces:**
- Consumes: `SttProvider`, `TtsProvider`, `TranslationProvider`, `LangCode`, `ReplyLanguage` (Task 1); `FakeStt`, `FakeTts`, `FakeTranslation` (Task 2).

### Task 5: VAD: Silero WASM Wrapper and Energy Fallback

**Files:**
- Create: `lib/voice/vad/energy.ts`, `lib/voice/vad/silero.ts`, `lib/voice/vad/select.ts`
- Test: `tests/voice/vad.test.ts`

The Silero wrapper runs only in the browser (`'use client'` on the hook that uses it, Task 10). It wraps `@ricky0123/vad-web`, which runs Silero VAD through ONNX Runtime WASM. The wrapper takes an injected `loadModel` so tests never load WASM. `level` is always the frame RMS, clamped to 0..1, so the orb reacts to loudness even when Silero says there is no speech. `speech` comes from the model probability (`> 0.5`) when Silero is used, and from the energy threshold otherwise.

**Interfaces:**
- Consumes: `VadProvider`, `VadFrameResult` (Task 1).
- Produces:
  - `rms(frame: Float32Array): number` (clamped to 0..1)
  - `class EnergyVad implements VadProvider { constructor(opts?: { threshold?: number }) }`, name `'energy'`, default threshold `0.02`
  - `interface SileroModel { process(frame: Float32Array): Promise<number> }` (returns speech probability 0..1)
  - `class SileroVad implements VadProvider { constructor(opts: { loadModel: () => Promise<SileroModel>; threshold?: number }) }`, name `'silero'`. `process` is synchronous per the interface, so it reads the most recent probability reported by the model (the model is driven by the browser audio worklet). Expose `async ready(): Promise<void>` that resolves when the model has loaded.
  - `selectVad(opts: { preferSilero: boolean; loadModel?: () => Promise<SileroModel> }): VadProvider`. Returns `SileroVad` only when `preferSilero` is true and `loadModel` is given; else `EnergyVad`.

### Task 8: Tool Schemas and Validating Orchestrator

**Files:**
- Create: `lib/voice/tools.ts`, `lib/voice/orchestrator.ts`
- Test: `tests/voice/orchestrator.test.ts`

Tools are `cart_update` (schema `CartUpdateSchema`), `delivery_intent` (schema `DeliveryIntentSchema`), and `respond` (schema `ReplySchema`). The model must make exactly one `respond` call and at most one action call. Each call's arguments are checked with that tool's schema. Any failure (unknown name, wrong count, schema error) is invalid. An invalid output is sent back once with a `repairNote` that lists the Zod issue paths. A second invalid output returns `SAFE_REPLY` with `action: { kind: 'none' }`. Nothing is returned as an action unless every check passed.

Pipeline per turn: `detectLanguage` → `translateForLlm` (timed as part of NLU) → `llm.complete` → parse and validate → at most one retry. The whole pipeline counts as one `nlu` stage in `TurnTimer`.

**Interfaces:**
- Consumes: `CartUpdateSchema`, `CartUpdate`, `DeliveryIntentSchema`, `DeliveryIntent` (Plan 01, `types/food-os.ts`); `LlmProvider`, `TranslationProvider`, `Clock`, `ReplyLanguage` (Task 1); `detectLanguage`, `replyLanguageFor`, `translateForLlm` (Task 7); `TurnTimer`, `TurnTiming` (Task 3).
- Produces (`lib/voice/tools.ts`):
  - `const ReplySchema = z.object({ reply_text: z.string().trim().min(1).max(400), reply_language: z.enum(['en', 'hi-en']) })`; `type Reply`
  - `const ActionPlanSchema = z.discriminatedUnion('kind', [z.object({ kind: z.literal('cart_update'), args: CartUpdateSchema }), z.object({ kind: z.literal('delivery_intent'), args: DeliveryIntentSchema }), z.object({ kind: z.literal('none') })])`; `type ActionPlan`
  - `const TOOL_DEFS: ToolDef[]`: `cart_update`, `delivery_intent`, `respond`, in that order
  - `const SAFE_REPLY: Record<ReplyLanguage, string>` = `{ en: 'Sorry, I did not catch that. Could you say it again?', 'hi-en': 'Maaf kijiye, samajh nahin aaya. Phir se boliye?' }`
- Produces (`lib/voice/orchestrator.ts`):
  - `interface VoiceDeps { llm: LlmProvider; translator: TranslationProvider; clock: Clock; systemPrompt?: string }`
  - `type TurnOutcome = 'ok' | 'retried' | 'safe_fallback'`
  - `interface VoiceTurnResult { action: ActionPlan; reply_text: string; reply_language: ReplyLanguage; outcome: TurnOutcome; detected_language: LangCode; timing: TurnTiming }`
  - `runVoiceTurn(deps: VoiceDeps, transcript: string): Promise<VoiceTurnResult>`
  - `parseToolCalls(calls: LlmToolCall[]): { ok: true; value: ActionPlan & { reply: Reply } } | { ok: false; issues: string }`

- Create: `lib/webrtc/transport.ts`, `lib/webrtc/livekit.ts`, `lib/webrtc/fake-transport.ts`, `lib/webrtc/session.ts`, `lib/webrtc/useVoiceSession.ts`
- Test: `tests/webrtc/session.test.ts`

The session controller holds all state logic and is tested with `FakeTransport`. The hook is a thin `useSyncExternalStore` wrapper and is marked `'use client'`. The LiveKit transport wraps `livekit-client`'s `Room`. It does not run in tests. The token is a parameter; minting it is out of scope (Open Items).

**Interfaces:**
- Consumes: `livekit-client` (Task 1 install); `selectVad` and `SileroModel` (Task 5) for the browser VAD in the hook.
- Produces:
  - `interface VoiceTransport { connect(url: string, token: string): Promise<void>; publishMicrophone(): Promise<void>; onLevel(cb: (level: number) => void): () => void; disconnect(): Promise<void> }`
  - `createLiveKitTransport(): VoiceTransport` (wraps `new Room()` from `livekit-client`; `onLevel` uses the local participant's audio level)
  - `class FakeTransport implements VoiceTransport` with `emitLevel(level: number): void`, `failNextConnect(message: string): void`, and counters `connects`, `disconnects`
  - `type SessionStatus = 'idle' | 'connecting' | 'live' | 'error'`
  - `interface VoiceSession { readonly status: SessionStatus; readonly level: number; readonly error: string | null; start(url: string, token: string): Promise<void>; stop(): Promise<void>; subscribe(cb: () => void): () => void }`
  - `createVoiceSession(transport: VoiceTransport): VoiceSession`
  - `useVoiceSession(createTransport?: () => VoiceTransport): VoiceSession` (in `useVoiceSession.ts`, `'use client'`)

```ts
// tests/webrtc/session.test.ts
import { createVoiceSession } from '@/lib/webrtc/session';
import { FakeTransport } from '@/lib/webrtc/fake-transport';

test('start moves idle to connecting to live and publishes the mic', async () => {
  const t = new FakeTransport();
  const s = createVoiceSession(t);
  expect(s.status).toBe('idle');
  await s.start('wss://example.livekit.cloud', 'token');
  expect(s.status).toBe('live');
  expect(t.connects).toBe(1);
});

test('level follows transport level events', async () => {
  const t = new FakeTransport();
  const s = createVoiceSession(t);
  await s.start('wss://x', 'token');
  t.emitLevel(0.4);
  expect(s.level).toBeCloseTo(0.4);
});

test('a failed connect sets status to error with the message', async () => {
  const t = new FakeTransport();
  t.failNextConnect('mic permission denied');
  const s = createVoiceSession(t);
  await s.start('wss://x', 'token');
  expect(s.status).toBe('error');
  expect(s.error).toBe('mic permission denied');
});

test('stop disconnects, resets level, and notifies subscribers', async () => {
  const t = new FakeTransport();
  const s = createVoiceSession(t);
  let notified = 0;
  s.subscribe(() => notified++);
  await s.start('wss://x', 'token');
  t.emitLevel(0.6);
  await s.stop();
  expect(t.disconnects).toBe(1);
  expect(s.status).toBe('idle');
  expect(s.level).toBe(0);
  expect(notified).toBeGreaterThan(2);
});
```

- [ ] **Step 3: Implement the five files**

- `session.ts`: `createVoiceSession` keeps `status`, `level`, `error` in closure state. `start` sets `connecting`, calls `transport.connect` then `publishMicrophone`, and sets `live`. Any throw sets `error` and `status = 'error'`. `onLevel` subscription is registered at start and removed at stop. Every state change calls the subscriber callbacks.
- `fake-transport.ts`: `FakeTransport` stores level callbacks and calls them on `emitLevel`.

- `useVoiceSession.ts`: `'use client'`; creates the session once with `useRef`; `useSyncExternalStore(session.subscribe, () => session.status ...)` pattern, exposing the session object.

### Task 11: Audio-Reactive Canvas Orb

**Files:**
- Create: `components/voice/orb-math.ts`, `components/voice/VoiceVisualizerOrb.tsx`
- Test: `tests/voice/orb-math.test.ts`

The scale math is pure and tested. The component draws a radial-gradient circle on a `<canvas>` each animation frame, scaled by `orbScale(level)`. It glows when `active` and holds a fixed scale when `prefers-reduced-motion` is set. `level` is the value from `VoiceSession.level` (Task 10) or `VadFrameResult.level` (Task 5). No automated visual test; visual check is in Acceptance.

**Interfaces:**
- Consumes: `VoiceSession.level` (Task 10).
- Produces:
  - `orbScale(level: number): number`: `NaN` and non-finite values map to 1. Otherwise `1 + 0.35 * clamp(level, 0, 1)`. Range is 1.0 to 1.35.
  - `ORB_REDUCED_MOTION_SCALE = 1.1`
  - `export function VoiceVisualizerOrb(props: { level: number; active: boolean; size?: number }): JSX.Element` (default export not used; named export; `'use client'`)

- [ ] **Step 1: Write the failing test**

```ts
// tests/voice/orb-math.test.ts
import { orbScale } from '@/components/voice/orb-math';

test('orbScale maps 0..1 onto 1.0..1.35 and clamps outside it', () => {
  expect(orbScale(0)).toBe(1);
  expect(orbScale(1)).toBeCloseTo(1.35);
  expect(orbScale(-1)).toBe(1);
  expect(orbScale(3)).toBeCloseTo(1.35);
});

test('orbScale treats NaN and Infinity as silence', () => {
  expect(orbScale(Number.NaN)).toBe(1);
  expect(orbScale(Number.POSITIVE_INFINITY)).toBe(1);

  let prev = orbScale(0);
  for (let i = 1; i <= 20; i++) {
    const s = orbScale(i / 20);
    expect(s).toBeGreaterThanOrEqual(prev);
    prev = s;
  }
});
```
